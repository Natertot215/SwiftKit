**Goal: this batch is NOT about adding new pages — it is about merge + populate + organize.**

- **Merge** — collapse sibling overload sprawl (e.g. 8 `onKeyPress` overloads → 1 family page; `Grid View` + `NSGridView` → 1 page) and any leaves whose docs are duplicates of each other.

- **Organize** — add a per-leaf `symbolName: String?` override and apply `text.document` to every article/overview leaf across the catalog (existing real, existing placeholder, target sections, and untouched sections alike). Cull leaves whose docs are empty/redirect/stub and can never be populated.

**Out of scope:** Adding leaves to the catalog. Authoring brand-new pages outside the target sections. Phase 6 final screenshot pass. Sidebar selection chrome AppKit bridge. Relocating legacy top-level `Pages/SwiftUI/*.swift` files.

**Target sections (the sections where placeholders get populated this batch):**
- SwiftUI: Toolbars, Search, Controls & Indicators, Menus & Commands
- AppKit: Animation, Views & Controls

**Architecture:**
1. Catalog data model gains an optional `symbolName: String?` on `Leaf`. Sidebar's existing framework-default icon path stays; the override wins when present.
2. A two-track agent triage sweep (SwiftUI + AppKit) classifies every catalog leaf into **component** / **article** / **merge-candidate** / **delete-candidate** and writes one Planning doc Nathan reviews before any catalog rewrite.
