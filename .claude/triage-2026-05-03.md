# SwiftKit catalog triage — 2026-05-03

Classifies every unauthored leaf (i.e. `pageBuilder: .placeholder`, not yet wired in `PageRegistry.swift`) into:

- **implement** — has a real, visible macOS-26 API that can be demoed in a child SwiftUI view (full GalleryPageScaffold worthwhile).

Page is just a header + signature + 2-3 paragraph description of what the API does and why it can't be rendered here.

## Patterns observed

**Almost everything in Immersive Spaces is visionOS-only** (23 of 25 → describe). Sensible to author one shared "visionOS-only — not renderable on macOS" describe template and reuse.

**Toolbars / Search has heavy enum + protocol surface** (`ToolbarItemPlacement`, `ToolbarRole`, `SearchScopeActivation`, etc.) — those are describe. Their consumer modifiers (`.toolbarRole(_:)`, `.searchScopes(_:scopes:)`) are implement where macOS supports them.

**Scene-level Commands family** (`commands`, `CommandMenu`, `CommandGroup`, `CommandsBuilder`, all `*Commands` conformances — 16 leaves) are all describe. They live at `App.body` scope only. Worth bundling several into a single "Commands" describe page.

**3D / spatial APIs** in layout, gestures, and view_styles (visionOS-only — `Padding3D`, `EdgeInsets3D`, `RotateGesture3D`, `transform3DEffect`, `rotation3DEffect(_:axis:anchor:)`) — all describe.

**iOS-only text input cluster** (`keyboardType`, `textInputAutocapitalization`, `EditButton`, `TextFieldLink`, dictation/keyboard types, etc. — 8 leaves) — all describe.

**AppKit integration is fully implementable** — every `NSHostingController` / `NSHostingView` / `NSGestureRecognizerRepresentable` API renders on macOS.

**Accessibility is fully implementable** with one exception (`AccessibilityQuickAction*` is watchOS only).

## What this means for the work plan

- **Net authoring work: ~734 implement pages + ~256 describe pages.** Describe pages are ~40 lines vs ~200 for an implement page → roughly 5× cheaper per page.
- **If we templatize describe** (single `DescribePage(title:, signature:, blurb:)` helper), the 256 describe pages collapse into one shared component + 256 short data entries. Probably a single afternoon batch.
- **The 734 implement pages** are the real authoring queue. Same parallel-Sonnet batch model as before, but now no token spend on fake-implementation pages.

## Bundle candidates (not classified separately, but worth noting)

Several describe entries are natural bundling candidates — sibling APIs that should probably share one page:

- All `*Commands` conformance types → 1 page (Commands family)
- All visionOS 3D geometry types (`UnitPoint3D`, `EdgeInsets3D`, `Padding3D`, `Edge3D`, `DepthAlignment*`, `Alignment3D`) → 1 page (visionOS 3D types)
- All Toolbar enum/option types → 1 page (ToolbarItemPlacement reference + sibling enums)
- All Search environment values + actions → 1 page (Search environment)

Doing this would knock the 256 describe pages down further — likely ~150 unique describe artifacts.
