## What happened

**Phase 3 — Page capture.** Bash script (`/tmp/swiftkit_capture.sh`) using `curl` + `jq` against Apple's JSON variant API. No AI summarizer in the loop = verbatim Apple content. Final capture (commit `cc7e40f`): **2,536 markdown files / 6.17 MB** across HIG (180 files, median 6.4KB), SwiftUI (1,707, median 1.4KB), AppKit (649, median 1.4KB). Zero empty folders. 5 `status:failed` stubs traced to URL-list typos (not capture failures); fixed and recaptured. Mirror confirmed clean.

**Capture scripts moved into project.** From `/tmp/` (non-portable, sandbox-untrusted) to `Documentation/_index/capture.sh` (full-mirror, idempotent, MIN_BYTES=2500 skip) and `Documentation/_index/recapture-targets.sh` (small TARGETS array for surgical re-fetches).

**`Documentation/` build crisis → relocated to project root.** `PBXFileSystemSynchronizedRootGroup` swept all 2,540 markdown files (originally at `SwiftKit/SwiftKit/Documentation/`) into the .app bundle's flat `Resources/`, causing duplicate-filename collisions (`width.md`, `windowgroup.md`, etc. exist in multiple framework subfolders) → BUILD FAILED. Resolved by `git mv SwiftKit/Documentation Documentation`. Bundle size dropped 6+ MB → 332 KB. New L-010 lesson written.

**Phase 4 sidebar baseline shipped.** Pure SwiftUI `List(selection:).listStyle(.sidebar)` in `SwiftKit/App/SidebarView.swift`. Three-tier disclosure (heading → folder → item). Sidebar pinned `min: 240, ideal: 280, max: 360` (L-009). `.navigationSplitViewStyle(.prominentDetail)` applied (L-003). Reference toggle heading at top.

**Sidebar selection chrome — Mail-style override DEFERRED.** Three pure-SwiftUI approaches failed:
1. `.environment(\.appearsActive, false)` — no-op for `List(.sidebar)` selection chrome on macOS 26.
2. Custom `.listRowBackground(...)` — even with `Color.clear`, triggers macOS 26 source-list grouping chrome (a "pure grey rectangle" container around rows).
3. Explicit `Label { Text } icon: { Image }` builder + per-element `.foregroundStyle` — breaks click-to-select hit testing.

Empirically verified: SwiftUI's `List(selection:).listStyle(.sidebar)` on a focused window draws emphasized state (solid `Color.accentColor` + white text); on unfocused, unemphasized (`NSColor.unemphasizedSelectedContentBackgroundColor` + accent text). SwiftUI exposes no public knob to suppress emphasized state on macOS 26. Mail/Finder/Notes use `NSOutlineView`-level overrides. Two paths captured in `Planning/sidebar-plan.md`. Shipped framework default.

**L-012 incident.** Sidebar selection pill in deleted `Sidebar/CatalogOutlineView.swift` had been overridden from `NSColor.unemphasizedSelectedContentBackgroundColor` to `NSColor.black.withAlphaComponent(0.7)` because a Figma node was read as "#000000 @ 70%" and committed as the spec. Runtime pill rendered darker than surrounding sidebar — inverse of Mail.app. Compounding factor: earlier dev-app screenshots had been captured with the SwiftKit window unfocused. Fix: reverted to semantic token, expanded L-012 doctrine, added "always focus window before screenshotting" rule to `macuix-rules.md`. The whole `CatalogOutlineView.swift` was eventually deleted in favor of pure SwiftUI `SidebarView.swift`.

## Decisions locked
- UI terminology rule established: labels in planning are descriptive hints, not canonical API names.
- Reference toggle sits at top of sidebar (`heading → item`, two tiers). SwiftUI/AppKit are three tiers. Order: Reference → SwiftUI → AppKit.
- `.safeAreaInset(edge: .bottom)` is the Apple pattern for bottom sidebar actions; only apply when there's actual content (empty insets break hit testing).
- Capture scripts canonical at `Documentation/_index/`.

## Pitfalls observed
- Earlier capture agents fabricated content from training data despite "verbatim" prompts. Spot-check by file size + comparison to raw JSON.
- Don't put dev-only artifacts inside `SwiftKit/SwiftKit/` — synchronized groups bundle them into the app.
